- Consumer semantics (`rerun_history`) are unchanged and remain fail‑closed: a non‑`Bot` author now yields `author.get("id") is None`, which still fails `author.get("id") != bot["node_id"]` and is additionally gated by `__typename != "Bot"`. No path becomes more permissive.

**Fixture (test_arm_capability_wiring.py:1510–1541, wired at ~1553)** — the projection is the security‑relevant improvement: the fixture can no longer hand back an `id` that the query did not request, so a passing test can no longer mask an unauthenticated binding. `totalCount` still derives from `self.comments`, so the `totalCount == len(nodes)` completeness check stays exercised.

### Nits (optional, non‑blocking)

1. **`re` fidelity — fixture:1523.** `r"\.\.\.\s+on\s+..."` requires whitespace after `...`. Valid GraphQL `...on Bot{id}` would fall through to `common` and spuriously raise `"Field does not exist on type Actor"`. Suggest `\s*`.
2. **Over‑strict fragment gate — fixture:1529.** `kind != "Bot"` rejects `... on User{login}`, which the real schema accepts. Intentional per the docstring, but the error text (`"Unsupported concrete actor selection"`) reads like a server error; consider naming it as a fixture limitation so a future author isn't misled.
3. **Selection anchoring — fixture:1518.** `query.index("author")` takes the *first* occurrence; if a second `author{...}` is ever added, the wrong block is parsed silently. A cheap `assert query.count("author{") == 1` would keep the failure loud.
4. **Test explicitness — test at ~1633.** `assertEqual(len(self.f.posts()), 1)` implies "no rerun" only because a claim must precede a rerun. Add `self.assertEqual(self.f.reruns(), [])` to assert the intent directly.
5. **Identity equivalence not asserted end‑to‑end.** The live check reports `all_bot_ids_present`, but not that GraphQL `Bot.id` equals REST `/users/{login}.node_id` for `sparq-orchestrator[bot]` — the actual comparison in `rerun_history`. If those ever diverge the behaviour is fail‑closed, but the *second* `rerun_history` call runs after the claim comment is posted, so the attempt would be stranded and need operator recovery. A one‑time read‑only equality check (by whoever holds credentials) before the next scheduled sweep would retire that risk cheaply.
6. **Fixture robustness.** The depth scan raises `IndexError` on an unbalanced query rather than a fixture‑level assertion; acceptable for a test double, worth one comment.

    def rerun_history(self, claim: dict, claimed_id: int | None = None) -> None:

            "-f", f"owner={self.owner}", "-f", f"name={self.name}", "-F", f"number={claim['pr']}"])
        try:
            viewer = response["data"]["viewer"]
            login = viewer["login"]
            history = response["data"]["repository"]["pullRequest"]["comments"]
            comments = history["nodes"]
            valid = (not response.get("errors")
                and history["pageInfo"]["hasPreviousPage"] is False
                and type(history["totalCount"]) is int and history["totalCount"] == len(comments))
        except (KeyError, TypeError):

            raise GhError("rerun refused: incomplete receipt history or authenticated identity")
        # The explicitly scoped workflow fallback has no actions:write. Reject it
        # BEFORE claiming anything; a known denial must not strand an attempt.
        if login != "sparq-orchestrator[bot]":
            raise GhError(
                f"rerun refused: authenticated login {login!r}; requires sparq-orchestrator[bot] "
                "(the workflow fallback has no actions:write)"

        # Resolve its authenticated login to the public Bot node, then bind authors
        # by both server node id and login; an author-controlled body supplies neither.

        if (not isinstance(bot, dict) or bot.get("type") != "Bot"
