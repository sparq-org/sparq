288:     /// any materialised (intermediate or final) result — the byte-accounted twin of
289:     /// `max_rows`. Where `max_rows` counts ROWS and so misses a query with FEW but very
290:     /// WIDE rows (many projected variables, or huge computed string literals), this bounds
291:     /// the estimated heap footprint of the id-level working set: `rows × width ×
292:     /// size_of::<Id>()` for each materialised intermediate, PLUS the bytes of any
293:     /// query-computed terms (BIND / aggregate / CONSTRUCT scratch) interned into the
294:     /// per-query local vocabulary. Checked cooperatively at the same coarse sites as
295:     /// `max_rows` (operator entry / per outer-loop iteration); a query whose estimate
296:     /// crosses it aborts with `"query budget exceeded (max-bytes)"`. The estimate is a
297:     /// portable LOWER bound on real heap (it ignores allocator overhead and `SmallVec`
298:     /// inline storage), so it is conservative in the SAME direction `max_rows` is — a blunt
299:     /// anti-OOM ceiling, not an exact RSS quota. `None` (the default) disables it; it

302:     /// Cross-thread cooperative cancellation flag. The executor observes `true`
