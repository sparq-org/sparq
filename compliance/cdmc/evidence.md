## E1 — Cataloguing surface (Component 2.1, maturity 4)

> **Posture (material):** the catalogue is **opt-in / default-OFF** — `descriptors.rs` is compiled
> only behind the `federation-descriptors` cargo feature (declared at
> `crates/sparq-server/Cargo.toml`, **not** in the default feature set), so in a stock build
> `GET /.well-known/void` returns `404`. It is maturity **3** (was 4): the merged `feature-matrix.yml` lane
> (#244, bead **sq-kzfi**) **builds, tests and clippies** `federation-descriptors`, but since the
> lean-CI change it runs nightly + dispatch only and the `ci-summary` aggregator is deleted, so a
> regression is detected post-merge rather than breaking the merge — the level-4 "gated" condition
> no longer holds.

- `.github/workflows/feature-matrix.yml` — GATING opt-in feature lane (#244). The
  `opt-in sparq-server (federation-descriptors, service, time-travel, geo, test-seams)` leg runs
  `cargo build`, `cargo test` and `cargo clippy --all-targets -D warnings` with
  `--features federation-descriptors,…` on the same stable toolchain ci.yml uses; nightly +
  dispatch only (not a required PR check). This is the evidence that 2.1 is regression-tested.
- `crates/sparq-server/src/descriptors.rs` — mounts `GET /.well-known/void` (W3C VoID) and the
  SPARQL 1.1 **Service Description** (`sd:Service`) endpoint; SD links to the VoID document, lists
  supported result formats and the default dataset. Generated by scanning the live snapshot. (Behind
  the `federation-descriptors` feature; 6 `#[test]`s now exercised by the `feature-matrix.yml` lane.)
- `crates/sparq-introspect/src/lib.rs` — `to_void(dataset_iri)` emits `void:triples`,
  `void:entities`, `void:distinctSubjects`, class/property partitions; `to_json()` / `to_text_summary()`
  the machine + LLM-grounding surfaces; characteristic sets, vocabularies (well-known recognition),
  observed *and* declared domain/range.
- `crates/sparq-introspect/README.md` — capability description; computed from sorted permutation
  indexes the store already keeps (no GROUP BY, no extra state) — proves the catalogue is cheap and
  always-fresh, not a stale side-table.

## E3 — Entitlements / access control (Component 3.1, maturity 3)

- `crates/sparq-solid/README.md` + `authindex.rs` + `rewrite.rs` — WAC (`.acl`) + ACP (`.acr`)
  fail-closed enforcement; per-`(WebID, client)` session restricted to the authorised graph set;
  inheritance, agent classes, groups, `allOf`/`anyOf`/`noneOf`, deny-overrides. Zero Solid-specific
  code in the engine (clean separation).
- `crates/sparq-server/src/http.rs` — `AuthPosture` (None / WriteOnly / ReadAndWrite, sq-zcby): an
  optional `Authorization: Bearer` write gate with a **constant-time** byte comparison (documented
  rationale: avoid a timing oracle; no `subtle` dependency to keep the SBOM surface minimal).
  Write detection keys on "does this mutate" (an UPDATE smuggled through the query path is a write).
- `research/feature-research-odrl-policy.md` — ODRL **usage** control is roadmap; the single-node
  gate over `sparq-solid` is documented as buildable-today, the federated disclosure-control design
  as research-grade (inherits the MPC/ZK blockers).

## E4 — Security controls (Component 4.1, maturity 4)

- `forbid(unsafe_code)` — present in 26+ crate `lib.rs` files; concentrated unsafe surface in
  `sparq-core` (mmap/dict-spill/SIMD = threat-model boundary **B5**), justified in the GX-5 register
  (#217, the `memsafety` slice).
- `.github/workflows/miri.yml` (nightly Miri), `fuzz.yml` (cargo-fuzz PR smoke + nightly),
  `codeql.yml` (SAST), `scorecard.yml` (OpenSSF, published), `supply-chain.yml` (cargo-deny +
  CycloneDX SBOM), `release.yml` (SLSA `attest-build-provenance` + buildkit `provenance: mode=max`).
- `crates/sparq-server/src/main.rs` — four-limit DoS guards: `--query-timeout` (30s),
  `--max-body-bytes` (1 MiB), `--max-concurrent` (32 → 429), `--max-results`/`--max-query-rows`
  (413), `--max-decompress-ratio` (20, zip-bomb guard), plus subscription caps. Env-overridable.
- `Dockerfile` — distroless, non-root, SHA-pinned base (the `cis` slice verifies the hardening).

## E6 — Lifecycle mechanism (Component 5.1, maturity 3)

- `crates/sparq-engine/src/update.rs` — every `GraphUpdateOperation` (INSERT/DELETE DATA,
  DELETE/INSERT…WHERE with graph templates + `USING (NAMED)`, CLEAR, DROP, CREATE, LOAD); the
  module header documents the v1→v2 named-graph data-loss fix (F19). Durability: each batch is
  **WAL-appended + fsync'd before apply**; CLEAR/DROP are durable **before** the ack; the
  cross-file partial-write race is closed by a **single `txn.log` commit frame** redone on `open`.
  In-memory graphs are byte-for-byte unchanged (commit steps are no-ops).
- `crates/sparq-engine/src/update.rs` `#[test]` block — crash-replay tests (drop without
  materialising/clearing the journal simulates a crash; every `GraphTarget` CLEAR captured/replayed).
- `crates/sparq-serve/src/lib.rs` — generation ring with bounded retention; `TimeTravelConfig` /
  `--time-travel-max-age` ages generations out → the retention/age-out hook for CD-5.

## E7 — Architecture & lineage (Component 6, maturity 4 / 2)
