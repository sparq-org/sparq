| Req | Property | Status | Evidence | Owner |
|---|---|---|---|---|
| I.2(a) | **Secure-by-default configuration**, with the ability to reset. | implemented & verified | `sparq-server` **fail-closed non-loopback bind** — refuses a non-loopback `--addr` unless `--allow-remote`/`SPARQ_ALLOW_REMOTE=1` *or* the surface is authenticated (sq-o4qf, `crates/sparq-server/src/main.rs`); loud no-auth startup WARNING; conservative DoS-limit defaults (below). | I.2(b) | **Protect from unauthorised access** by appropriate control mechanisms (incl. authentication). | audit-ready (operator split) | **Optional** Bearer auth: `--auth-token`/`SPARQ_AUTH_TOKEN`, read-gating `SPARQ_AUTH_TOKEN_READ` (`crates/sparq-server/src/main.rs`). **No per-user authz/session** by documented design — boundary **B3** "front with a gateway / sparq-solid" (`research/threat-model.md`, `Dockerfile` header, `crates/sparq-server/README.md`). | I.2(c) | **Protect confidentiality** of stored/transmitted/processed data (e.g. encryption at rest/in transit). | audit-ready (operator split) | sparq is a data engine processing operator-supplied RDF; **transport encryption (TLS) is terminated by the operator's reverse proxy** (documented, `Dockerfile`/server README) — a bare Bearer token over plaintext is called out as sniffable. | I.2(d) | **Protect integrity** of stored/transmitted/processed data, commands, config, against unauthorised manipulation. | implemented & verified (engine) + operator (transport) | Memory-safety posture: `#![forbid(unsafe_code)]` in 31/36 crates, concentrated unsafe in `sparq-core` exercised by Miri + fuzz + oracle (`compliance/memsafety/`, `.github/workflows/{miri,fuzz}.yml`); input validation at parser/server boundary (`CONTRIBUTING.md`). Transport integrity = operator TLS. Supply-chain integrity of the artifact: SLSA provenance + SHA256SUMS (below). **Build integrity:** the release build is `--locked` + provenance-attested, and a documented double-build shows it is **byte-identical apart from 22 bytes** from **one** named non-determinism source — [`../slsa/reproducible-build.md`](../slsa/reproducible-build.md) (GX-8/sq-toze.9; bit-for-bit enforcement is the residual). | sparq (engine) + operator (transport) |
| I.2(e) | **Process only data adequate, relevant, limited** to what is necessary (data minimisation). | audit-ready (operator-owned) | sparq processes exactly the RDF the operator loads + the SPARQL queries issued; it collects no telemetry of its own. **What personal data is loaded is the operator's (controller's) decision** — see the privacy worktree `compliance/data-flow.md` / `dpia.md`. sparq's job is to not *expand* the data (no leakage in errors/logs — ASVS V7, `CONTRIBUTING.md`). | operator (controller) |
| I.2(f) | **Protect availability** of essential functions, incl. resilience/mitigation against DoS. | implemented & verified | Server DoS limits: `--max-body-bytes` (request-size cap), `--max-decompress-ratio` (**zip-bomb guard**, sq-ebii), `--max-concurrent` (load shedding), `--max-results` / `--max-query-rows` (413 beyond), subscription caps (`crates/sparq-server/src/main.rs`). Reachable-panic / unbounded-allocation from untrusted input treated as in-scope DoS bugs (`SECURITY.md`, `CONTRIBUTING.md`); fuzzers guard the parser/loader (`.github/workflows/fuzz.yml`). | sparq |
| I.2(g) | **Minimise own negative impact** on availability of other devices/networks. | implemented & verified | The binary is a single bounded process with the limits in I.2(f); it opens no outbound connections except SPARQL federation the operator's query requests (SERVICE) — and that is operator-driven query content. No background beaconing/telemetry. | sparq |
| I.2(h) | **Limit attack surfaces**, including external interfaces. | implemented & verified | Distroless **non-root**, no-shell runtime image (`Dockerfile`, `gcr.io/distroless/cc-debian12:nonroot`); minimal exposed surface (one HTTP endpoint + optional WebSocket); opt-in capability crates (geo/text/vectors/…) not in the default build; `#![forbid(unsafe_code)]` shrinks the memory-unsafe surface to `sparq-core`. | sparq |
| I.2(i) | **Reduce impact of incidents** via exploitation-mitigation techniques. | implemented & verified | Memory safety (Rust + forbid-unsafe) removes whole vuln classes; fail-closed bind + limits bound blast radius; container is read-only-friendly + non-root (privilege containment). Hardware-tier release builds do not disable mitigations. | sparq |
| I.2(j) | **Record and monitor** relevant internal activity (security-relevant logging), incl. opt-out. | audit-ready (operator split) | Server emits structured logs + metrics (`crates/sparq-server/src/metrics.rs`, hardening/tracing stack) without leaking RDF/SPARQL content or paths (ASVS V7, `CONTRIBUTING.md`). **Security monitoring/alerting/retention is the operator's** SIEM concern; sparq provides the signal, not the SOC. | sparq (signal) + operator (monitoring) |
