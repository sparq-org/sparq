# Noir query package for the Solid App Suite (16 Nov 2026)

The scoped-query package is ready: **@sparq-org/zk-query 0.1.8**, built from sparq main at `95c7b325`
(PR #7402, merged). This is the package for the paths that the result-proof package cannot serve:
the issuer-scoped GRAPH form with a different issuer per fact, holder binding, and the absence and
totals paths. All six target queries are catalogued with their full credential envelopes:
insurance 1a and 1b, trial eligibility, and the recycled-content MIN, SUM and HAVING forms.
Each one proves and verifies from Node in CI.

It is research-grade and has not been externally audited.

## Download

The tarball is 403,613,492 bytes, which is over GitHub's 100 MB file limit, so it ships in five parts
on the `solid-answer-dist` branch. Fetch and join them:

```sh
for i in 00 01 02 03 04; do
  gh api -H "Accept: application/vnd.github.raw" \
    "repos/sparq-org/sparq/contents/sparq-zk-query-95c7b325.tgz.part-$i?ref=solid-answer-dist" \
    > sparq-zk-query-95c7b325.tgz.part-$i
done
cat sparq-zk-query-95c7b325.tgz.part-0* > sparq-zk-query-95c7b325.tgz
shasum -a 256 sparq-zk-query-95c7b325.tgz
# expect d01ad664fcac41d918309f19bbd900a54a66feb5f67e977b7b589523c65543f3
npm install --offline ./sparq-zk-query-95c7b325.tgz
```

`SHA256SUMS` on the branch lists the whole file and each part. The package records its source commit
in `wasm/provenance.json` (`95c7b325…`, no uncommitted changes). Most of the size is the pinned
proving reference string (CRS), which ships inside the package, so proving needs no download.

## What you need to prove

- **Node 24 or newer.** The package is ESM only: `import` works, `require` does not.
- **Native proving is the default, and the six targets prove natively only.** It runs two pinned
  binaries as local child processes, offline: `nargo 1.0.0-beta.21` and `bb 5.0.0-nightly.20260324`.
  Install them with `noirup -v 1.0.0-beta.21` and `bbup -v 5.0.0-nightly.20260324`. Then set
  `SPARQ_NARGO` and `SPARQ_BB` to their paths, or pass `backend: { type: 'native', nargoPath, bbPath }`.
  Neither binary is looked up on PATH, and neither has a default. Each binary is checked against the
  SHA-256 and version in `assets/toolchain.pins.json` before it runs. If a binary is missing, the call
  refuses with `missing binary`. If a binary differs from its pin, it refuses with `binary pin mismatch`.
- **The binary pins are for linux-x64 only in this build.** On a Mac, prove inside a linux/amd64
  container or on a Linux x64 machine. Verifying needs no native binaries and works on any platform
  with Node 24.
- The opt-in WebAssembly prover (`backend: 'wasm'`) handles only the smaller catalogue entries,
  up to a dyadic circuit size of 2^21. The six targets are larger, so it refuses them up front.

## Policy and layout

- **Trust policy.** `trustMembers: [{ issuer, verificationMethod, publicKey }]`. Its key set must equal
  `trustedIssuers`. This is the same shape that zk-result 23d2f3db accepts, so one policy object serves
  both packages. See the README's API and "Credential envelope" sections, which also cover the
  optional envelope fields: holder binding, status snapshots, validity, earliest-created and row bounds.
- **Public-input layout.** See the README's "Public-input layout" section. It is generated from the
  query crate and checked for drift in CI.
- **Calls.** `issuerKeygen`, `issue` (and test-only `testIssuerKeygen`, `testIssue` with a seed),
  `request({ query, policy, nonce })`, `prove({ request, credentials, backend })`, and
  `verify({ request, presentation, seenNonces })`. `verify` returns
  `{ verified, released, reason?, report }`. It rebuilds the request in Rust, checks the key against
  the embedded catalogue for the plan hash, verifies the proof, rechecks freshness, and consumes the
  challenge last.

## Checks we ran on this tarball

- It installs offline into an empty directory.
- From the installed copy on Node 24, `target-insurance-1a` proved with the native backend, verified
  true, and released `true`.
- The test suite does not ship in the package. At the same commit, the repository's offline suite
  passes 36 of 36.
- In CI, the live suite proves and verifies all six targets from Node. It also checks the refusals for
  revoked, stale-snapshot, missing-holder, foreign-holder, expired and stale credentials.
