# STABILITY — FO-KM Metric 3 (LLM ontological-commitment stability probe)

> 🤖 **SPARQ agent.** Measurement record for **Metric 3** of epic **sq-mztg8**
> (bead `sq-mztg8.3`) — the Köhler–Neuhaus-style cross-session contradiction probe,
> re-run per model. Metric 1 (agent KM-task accuracy over the PKG) is the sibling
> record `RESULTS.md`; nothing here changes it.
>
> **This is a PILOT.** The design record flags Metric 3 as a *stretch* arm and the bead
> carries `needs-maintainer-steer` on the grading protocol and N. The protocol below was
> pre-registered — the probe battery (`stability_probes.jsonl`) and the grader
> (`stability_analyze.py`) were both written and committed **before** any session ran —
> but N, K and the arm set are the author's proposal, not a maintainer-ratified design.
> See **§ Open questions**.

## The question

Köhler & Neuhaus (*The Mercurial Top-Level Ontology of LLMs*, FOIS 2024,
arXiv:2405.01581) found that an LLM asked the same top-level categorial question in
separate sessions does not reliably give the same answer: ontology terms have fixed
compositional semantics, but an LLM emits tokens stochastically by context, so its
implicit top-level ontology is *mercurial*. Their study is scoped to **GPT-3.5**, and the
design record is explicit that it must be **re-run per model** rather than assumed to
carry over.

The FO-KM adaptation asks the epic's question on top of that: **does the FO choice change
the instability?** If an explicit FO in context acts as an external scaffold, the grounded
arms should contradict themselves less than the ungrounded control.

## Method

- **Battery.** 12 forced-choice probes (`stability_probes.jsonl`, generated by
  `build_probes.py`) over a closed four-label set — `OCCURRENT` / `CONTINUANT` /
  `ABSTRACT` / `UNDECIDABLE`. Two strata:
  - **SC (scaffolded, 8)** — the four PKG classes the overlays type (Task / Finding /
    Source / Technique), each as a *generic* probe and an *instance* probe over a real
    individual from `crates/sparq-kb/ingest/pkg-instances.ttl`. The generic/instance
    probes form **4 pairs**: a session that puts a kind in one category and a member of
    that kind in another has contradicted itself *within* the session.
  - **US (unscaffolded, 4)** — subjects no overlay types (a merged PR, a CI gate, the
    SPARQL standard, a benchmark run). These measure the model's own implicit top-level
    ontology, and whether an in-context FO **transfers** past the entities it covers.
- **Arms (3).** `ungrounded` (control, no ontology in context) · `gufo` (a rich FO that
  *does* draw the occurrent/continuant axis) · `schema-org` (the ratified fluent facade,
  which does *not* — `schema:Action` and `schema:CreativeWork` are sibling branches under
  `schema:Thing`). Both scaffolds are transcribed from the committed `overlays/*.ttl`, so
  these are the same ontologies Metric 1 ran. The scaffold supplies the FO's **top-level
  taxonomy only**, deliberately *not* the PKG-class→FO mapping the overlay asserts —
  otherwise the SC stratum would be a lookup rather than an act of categorisation.
- **Sessions.** K = 5 fresh sub-agent sessions per (model, arm) cell, 3 models × 3 arms ×
  5 = **45 sessions**. Each session got the battery once, in a **fixed order**, with no
  tools and no repository access, and emitted 12 `pNN: LABEL` lines. Order is held
  constant on purpose so that disagreement is attributable to sampling rather than to a
  permuted presentation.
- **Grading — deterministic, no model in the loop** (design §5.2 anti-circularity, the
  same rule as Metric 1's `analyze.py`). Every quantity is a count over the closed label
  set. Raw session text is committed in `metric3-sessions.jsonl`, so the parse step is
  auditable rather than pre-digested.
- **Prompt-level, not tool-level, on purpose.** Metric 1 measures how well an agent
  *wields* an FO through `pkg-query`; Metric 3 measures whether an explicit FO
  *stabilises* the model's categorial commitments. The tool is not part of that construct,
  and leaving it out removes tool-variance from the measurement.

## The findings

1. **The Köhler–Neuhaus mercuriality is weak-to-absent at these tiers on this battery.**
   The ungrounded contradiction rate is 0.17 / 0.00 / 0.08 (haiku / sonnet / opus) — most
   probes are answered identically in all five sessions, and the decisiveness guard
   confirms this is *commitment*, not abstention (`und` is 0.00 for eight of nine cells).
   The GPT-3.5-era result should **not** be assumed to carry over to current models, which
   is exactly what the design record asked this metric to check.

2. **An explicit FO does NOT reliably reduce cross-session contradiction — the direction
   flips across models.** For haiku the gUFO scaffold removed the instability
   (0.17 → 0.00); for opus it *increased* it fourfold (0.08 → 0.33). schema.org left haiku
   unchanged (0.17) and doubled opus (0.08 → 0.17). With one measurement per cell this is
   a **sign-unstable, unsupported** effect — the "FO-as-external-scaffold reduces
   ontological contradiction" thesis of design §4.2 is **not confirmed** by this pilot.
   (Compare the sibling instability in Metric 2 / `sq-p5ro8`, which also sign-flips across
   slices.)

3. **Where the scaffold *does* help is WITHIN a session, not across sessions.** The `ws`
   column — a session putting a *kind* in one category and a *member of that kind* in
   another, which is a contradiction that sampling cannot explain — is the largest
   instability signal in the whole run, and the FO scaffold cuts it hardest exactly where
   it is worst: opus 0.45 ungrounded → 0.10 under either scaffold; haiku 0.50 → 0.25
   (gUFO) / 0.40 (schema.org). This is the one positive result for the scaffold thesis,
   and it is on a **different construct** from the one the design record proposed to
   measure.

4. **No model respected the boundary of the ontology it was given.** `adh` for the
   `schema-org` arm is **0.00 in every cell**: the schema.org fragment cannot decide an
   occurrent/continuant question (its own overlay header says so — there is no
   endurant/perdurant axis), so the entailed answer on all 8 SC probes is `UNDECIDABLE`,
   and no model ever gave it. Models answered anyway. Adherence to gUFO — an ontology that
   *can* decide — was also only partial and did **not** rise with tier
   (haiku 0.62 > sonnet 0.38 > opus 0.35). This is the Köhler–Neuhaus mechanism showing up
   as **over-commitment** rather than as cross-session flapping: the models are stable, but
   stable on *their own* implicit categories rather than on the supplied ontology's.

5. **The instance probes are where the disagreement concentrates.** `p02` (one particular
   closed task) is unstable in both haiku-ungrounded and opus-ungrounded, and `p01`/`p02`
   (the Task pair) plus `p06` (AGENTS.md) account for most of opus's grounded-arm
   contradictions. The generic/instance split is doing real work: it is easier to get a
   model to agree with itself about a *kind* than about a *particular*.

## Honest caveats

- **N = 12 probes, K = 5 sessions, 3 arms, 3 model tiers, single run.** Point estimates
  over 12 probes move in steps of ~0.08; a `cs` difference of one probe is one step. The
  cross-model *direction flip* in finding 2 is larger than one step (0.08 → 0.33 is four
  probes) but the pilot is **not powered** to resolve small effects, and N/K are precisely
  what the bead defers to the maintainer.
- **Sampling temperature was not controlled or observed.** All 15 sonnet sessions returned
  **byte-identical** answers across all three arms. That is either genuine stability or a
  low-effective-temperature / mode-collapse artefact, and this harness cannot tell the two
  apart. Haiku and opus *did* vary between sessions, so the harness is not globally
  deterministic — but the sonnet row should not be read as a strong stability claim.
  Resolving this is the first open question below.
- **Serving model ids were NOT independently verified.** The `model` field records the
  *requested* tier (`haiku` / `sonnet` / `opus`) passed to the sub-agent dispatcher. Unlike
  the Fable re-run in `RESULTS.md`, which mined `message.model` per assistant line and
  gated on it, this run has **no model-id validity gate** — a silent model substitution
  would not have been caught.
- **"Cross-session" here means fresh sub-agent sessions inside one orchestrating run**, not
  independent sessions on different days or through different accounts. They share a
  harness and a system prompt. Köhler & Neuhaus's separation was stronger.
- **The fixture's `fo_label` is the overlay's own asserted mapping, not ground truth.**
  `adh` is only ever read down a single arm's row: gUFO and schema.org disagree with each
  other by construction, and neither is "correct". A low `adh` means the model departed
  from *that* ontology, not that it was wrong about the world.
- **Two of the epic's overlays are not run as arms.** `no-fo` would duplicate the
  `ungrounded` control (its overlay asserts no FO typing, so at prompt level the two
  contexts are the same). **DOLCE-DUL is deferred** because `dul:Description` — the
  overlay's target for `pkg:Finding` — is a *non-physical endurant* in DUL and maps cleanly
  to neither `CONTINUANT` nor `ABSTRACT` under this label set; inventing a gold would put a
  fabricated entailment in the fixture. Adding it needs a mapping decision (open question 3).
- **All figures are runtime / NON-CANONICAL** (work-box sub-agent sessions). Run artifacts
  are regenerable; the committed artifacts are this record, the frozen battery, and
  `metric3-sessions.jsonl`.

## Open questions — `needs-maintainer-steer`

The bead is explicitly blocked on the grading protocol and N. Concretely:

1. **Sampling control.** Should the protocol pin (and record) a sampling temperature, and
   report cs at a stated temperature? Without it, "stability" conflates model behaviour
   with harness configuration — and the byte-identical sonnet row above is the symptom.
   This is the single change that would most improve the metric's meaning.
2. **N and K, and a decision rule.** 12 probes × 5 sessions is a pilot. What N/K should a
   ratified run use, and is there a pre-registered margin at which "the FO scaffold changes
   stability" would be *accepted* or *rejected* — the Metric-3 analogue of the K1–K5
   kill-criteria in design §4.3? This pilot deliberately registers no kill-criterion,
   because inventing one after seeing a sign-unstable result would be unfalsifiable.
3. **Which construct is the metric?** Finding 3 says the scaffold's real effect is on
   *within-session* generic/instance coherence (`ws`), not on the cross-session
   contradiction the design record named. Should `ws` be promoted to a co-headline, and
   should the battery grow more entailment pairs to measure it properly?
4. **Arm set.** Add DOLCE-DUL (needs the `dul:Description` mapping call above), and/or the
   gist / BFO overlays if `sq-givgo` lands them? Add a Fable-tier subject, as the Metric-1
   re-run did?
5. **Does this metric read on any decision?** Metric 1 feeds the facade choice
   (`sq-mztg8.4`/`.5`, ratified schema.org-as-top). Finding 4 — that no model respects an
   ontology's expressive boundary and none of them abstained — is arguably the most
   actionable result here, but it currently informs no bead. Should it?

## Reproduce

```bash
python3 bench/fo-km/build_probes.py --check                 # battery matches its generator
python3 bench/fo-km/build_probes.py --emit-prompt gufo      # the exact per-session brief
python3 bench/fo-km/stability_analyze.py                    # self-check, no run needed
python3 bench/fo-km/stability_analyze.py bench/fo-km/metric3-sessions.jsonl
```

The battery, the three arm scaffolds, the grader and all 45 raw session answers are
committed. `stability_analyze.py` re-derives every number in this record from
`metric3-sessions.jsonl` — no step of the grading depends on a model.

The no-argument mode is an **asserted** self-check, not a description: hand-computed
fixtures pin every quantity above against awkward inputs (a missing answer, a restated
probe id, an out-of-vocabulary label, an abstention), it re-derives every column of the
table above from the committed sessions, and it exits nonzero on any mismatch. The
denominators are stated explicitly at the top of the grader — in particular **`cs_dec`
counts only probes answered in *every* session with no abstention**, so neither
abstaining nor staying silent can buy a cell a better decided-contradiction rate.
`--strict` additionally refuses to report at all over a cell with a missing or unparsed
answer.
