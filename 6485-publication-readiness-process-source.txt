3: # feature-OFF wasm-bundle change declarations (mechanism V2)
4: 
5: The `vectorized-feature-off` gate (leg 2,
6: `.github/workflows/vectorized-feature-off.yml`) builds the feature-OFF `sparq-wasm`
7: bundle from the **base** tree and the **head** tree in the same CI run and compares
8: them **byte-for-byte**. Identical bytes pass automatically. If the bytes differ, the
9: change must be **declared** — otherwise the gate fails (the whole point: an accidental
10: `vectorized`/default-path leak into the feature-OFF build is caught).
11: 
12: ## How to declare
13: 
14: If your PR *intentionally* changes always-compiled engine/core code in a way that moves
15: the feature-OFF bundle bytes, add **one file** named after your PR number:
16: 
17: ```
18: bench/feature-off-declarations/<PR-number>.json
19: ```
20: 
21: with the shape:
22: 
23: ```json
24: {
25:   "pr": 1234,
26:   "date": "2026-07-07",
27:   "reason": "one line on what always-compiled change moves the feature-OFF bytes"
28: }
29: ```
30: 
31: The gate is satisfied when the head tree's declarations directory contains at least one
32: `<digits>.json` (or `.md`) file the base tree's does **not** — a set difference on the
33: directory listing. Only names matching `<digits>.json|md` count as declarations, so this
34: `README.md` (and any `.gitkeep`) is ignored.
35: 
36: ## Why per-PR files (V2)
37: 
38: The previous mechanism stored one scalar `change_token` in
39: `bench/feature-off-declaration.json`. Every declaring PR edited the **same line**, so the
40: first declared PR to merge made every other declared PR textually **CONFLICTING** in git
41: (`#1720` and `#1718` both went `DIRTY` after `#1726`'s declaration merged). The gate check
42: was order-independent but the file was not. Per-PR files remove the shared line: different
43: PRs add different files, so git never conflicts regardless of merge order.
44: 
45: The legacy scalar file `bench/feature-off-declaration.json` is **retired** (frozen, kept
46: parseable). During the transition window the gate still accepts a scalar-token inequality
47: so in-flight pre-V2 branches keep working; new PRs must use a per-PR file here instead.
48: 
49: ## Scope
50: 
51: This declaration governs **intent** (did you mean to change the feature-OFF bytes at all?).
52: The **size** of an accepted change is governed separately, unchanged, by the
53: `metrics.wasm_bundle_bytes` floor ratchet (±2% band) in `bench/perf-baseline.json` /
54: `bench.yml`. A change moving the bundle > ±2% must also raise that floor.
55:

137: An **intentional always-compiled change** — a hot-path optimisation, a refactor of code the
138: default build ships — is refused on purpose. Its author is asserting *intent*, and intent cannot
139: be derived; write the declaration by hand, as `3679.json` and `3755.json` do.
140: 
141: Three deliberate limits:
142: 
143: * The tool **does not make the leg pass**. It writes a file that still has to be committed, so
144:   the escape hatch stays inside the reviewed diff. An auto-passing gate whose derivation had a
145:   hole would be exactly the rubber stamp this leg exists to prevent.
146: * Every obligation builds into its **own** target directory. Sharing one warm directory
147:   across the materialised trees was tried for speed and reverted: on #4350 it reported a
148:   299-line `crates/sparq-engine/src/exec.rs` rewrite as *byte-identical* to its base, because
149:   `git archive` stamps each tree's files with its commit time and cargo's freshness check is
150:   mtime-based. A false "identical" is the one outcome that would auto-declare a real code
151:   change, so cold builds are the price.
152: * It attributes against the **merge base**, not `pull_request.base.sha`. Those differ whenever a
153:   branch is behind its base, and leg 2 itself compares `base.sha` — so on such a PR the leg's
154:   reported difference also carries, in reverse, base-branch commits the PR does not have. The
155:   tool says so in its output rather than attributing them to the PR.

181: # MECHANISM V2 (sq-v3nel-v2): a declaration FILE is bench/feature-off-declarations/
182: # <PR-number>.json (or .md). Only names matching <digits>.json|md count as declarations,
183: # so a README.md / .gitkeep in the directory is NOT mistaken for a declaration.
184: _DECL_FILE_RE = re.compile(r'^\d+\.(?:json|md)$')
185: 
186: 
187: def _list_declaration_files(dir_path: str | None) -> set[str]:
188:     """Return the set of per-PR declaration file names in a declarations directory.
189: 
190:     Fail-SAFE: a None / missing / non-directory path reads as the EMPTY set, so an absent
191:     directory can never be mistaken for a declaration (keeps the gate fail-closed).
192:     Only names matching <digits>.json|md are counted (README.md/.gitkeep are ignored).
193:     """
194:     if not dir_path or not os.path.isdir(dir_path):
195:         return set()
196:     return {name for name in os.listdir(dir_path) if _DECL_FILE_RE.match(name)}
197: 
198: 
199: def _new_declaration_files(base_dir: str | None, head_dir: str | None) -> set[str]:
200:     """Return declaration files the HEAD tree has that the BASE tree does NOT (set diff).
201: 
202:     A non-empty result means the PR ADDED at least one bench/feature-off-declarations/
203:     <PR-number>.json — i.e. it DECLARED an intentional feature-OFF byte change under
204:     mechanism V2. Because each PR adds a distinctly-named file, this never collides with
205:     another declaring PR (unlike the old shared scalar token line).
206:     """
207:     return _list_declaration_files(head_dir) - _list_declaration_files(base_dir)
